# CodeMaze — Game Screenshots

This document describes the screenshots recommended for showcasing CodeMaze.

All screenshots should be captured from the actual running game. Only include features that are implemented and working.

## 1. Main Menu

**Suggested filename:** `main-menu.png`

Capture:
- Game title.
- Main menu options.
- Overall game interface.

## 2. Level Selection

**Suggested filename:** `level-selection.png`

Capture:
- Available game levels.
- Level selection interface.
- Any displayed level information.

## 3. Maze Gameplay

**Suggested filename:** `maze-gameplay.png`

Capture:
- Generated maze.
- Player position.
- Maze walls and paths.
- Exit and challenge locations, if visible.

## 4. Programming Challenge

**Suggested filename:** `programming-challenge.png`

Capture:
- A C++ programming question.
- Four answer options.
- Timer and hint option, if available.

## 5. Adaptive Learning or Performance

**Suggested filename:** `adaptive-learning.png`

Capture:
- Topic-wise performance or learning information.
- Difficulty selection or adaptive question behaviour.
- Any visible learning statistics.

If adaptive learning is not directly displayed, use a genuine gameplay screenshot showing a question selected after previous attempts. Do not create a fake dashboard.

## 6. Result Screen

**Suggested filename:** `result-screen.png`

Capture:
- Final score.
- Correct and incorrect answers.
- Topic-wise performance, if displayed.
- Replay or next-level options, if available.

## 7. Suggested Folder Structure

```text
docs/
└── screenshots/
    ├── main-menu.png
    ├── level-selection.png
    ├── maze-gameplay.png
    ├── programming-challenge.png
    ├── adaptive-learning.png
    └── result-screen.png
```

## 8. Screenshot Guidelines

- Capture screenshots from the actual running CodeMaze game.
- Prefer PNG format.
- Keep text and game elements readable.
- Use consistent window dimensions where practical.
- Avoid cropping important gameplay elements.
- Do not expose personal information.
- Do not use mockups or fabricated gameplay screens.

## 9. README Integration

After capturing the screenshots, selected images can be displayed in the main README using relative paths.

Example:

```markdown
![Maze Gameplay](docs/screenshots/maze-gameplay.png)
```
